# OdIna-Campusflow — Ticket Management CLI

A beginner-friendly Python command-line project for creating and managing IT support tickets.

## Features

- Create tickets with automatic IDs (`T001`, `T002`, ...).
- Validate ticket titles, categories, urgency, and affected-user counts.
- Calculate priority using the project rules.
- List and find tickets, assign a ticket to a team member, and update its status.
- View a summary report.
- Save tickets to and load tickets from a JSON file.
- Run automated unit tests using Python's built-in `unittest` module.

## Requirements

- Python 3.10 or newer (no third-party packages are required).

## Run the program

From the project root directory:

```bash
python3 main.py
```

The program stores tickets in `data/tickets.json` when you choose **Save tickets**. The data file is intentionally ignored by Git so local ticket data is not accidentally committed.

## Run tests

From the project root directory:

```bash
python3 -m unittest discover -s tests -v
```

## Ticket fields

Each ticket has these fields:

- `id`: unique ID generated by the application
- `title`: short description of the issue
- `category`: `Network`, `Hardware`, `Software`, or `Other`
- `urgency`: `low`, `medium`, or `high`
- `affected_users`: positive whole number
- `priority`: calculated as `low`, `medium`, `high`, or `critical`
- `status`: initially `open`; can be `open`, `in_progress`, `resolved`, or `closed`
- `assigned_to`: a person's name, or `null` when unassigned

## Priority rules

The rules are evaluated in this order:

1. High urgency **and** 10 or more affected users → `critical`
2. High urgency **or** 10 or more affected users → `high`
3. Medium urgency **or** 3 or more affected users → `medium`
4. Otherwise → `low`

## Suggested team workflow

1. Engineer A reviews ticket creation and validation in `campusflow/tickets.py`.
2. Engineer B reviews ticket workflow and persistence in `campusflow/workflow.py` and `campusflow/storage.py`.
3. Review the tests together and add tests whenever behavior changes.
4. Read `docs/design-decisions.md` and complete `docs/ai-learning-log.md` together.
5. Run the full test command before merging changes.
